# CVE-2026-86950 — CoreGraphics out-of-bounds write

| Field | Value |
|---|---|
| Component | CoreGraphics (image/PDF decode path) |
| Class | out-of-bounds write |
| Our status | **reproduced — DoS** (crash confirmed, primitive not) |
| Build | iOS 27.0.1 (24A446), iPhone 14 (A15) |

## Why it is in the register

This was one of the earliest targets: a public CoreGraphics OOB write, reachable by handing the
system a file. A probe suite written for it produced consistent crashes, which is why it appears
here rather than being dropped silently. (The specific CG probe is not among the sources published
here; the crashes it produced are described below.)

## What was measured

Probe runs against the affected decode path crashed the rendering process reproducibly. The crash
reports show `EXC_BAD_ACCESS` in CoreGraphics frames, with the faulting address derived from image
geometry rather than from a value in the file.

That last point is the reason the branch stopped: geometry-derived addresses give a crash, not a
controlled write. No run produced a fault address that followed an attacker-supplied 64-bit value,
and no run produced a controlled data payload.

## Verdict

Documented as a denial of service in a system rendering process. It was not developed further and
is not part of any chain.

## Falsifier

A run whose fault address equals a value taken from the input file, or whose written data is
attacker-chosen. Absent that, the branch stays a crash generator.

## Note on naming

This CVE was tracked in early notes as "the CG OOB write". The register keeps the identifier so a
reader can match it against public material; the measurement, not the identifier, is what decides
the status.
