# CVE-2026-112705 — AppleAVE2 temporal-layer count

| Field | Value |
|---|---|
| Component | `com.apple.driver.AppleAVE2` (HEVC encoder), property `iNumberOfTemporalLayers` |
| Class | missing input validation in kernel, reachable from a media client |
| Our status | **reproduced — DoS** |
| Build | measured on 27.0 (24A437); re-check on 24A446 pending |
| Related writeup | [`docs/03-ave2-temporal-layers.md`](../docs/03-ave2-temporal-layers.md) |

## What changed in 27.2

The 27.2 encoder gained a runtime bound where the audit build has only an assertion (compiled out
in release):

```
0 <= pInfo->uPropCfg.sHEVC.iNumberOfTemporalLayers &&
     pInfo->uPropCfg.sHEVC.iNumberOfTemporalLayers <= 7
```

with the message `number of temporal layers (prop) is out of range %d %d %d`, and the check is
the first instruction sequence reading `[x20, #0x768]` guarded by `mov w9, #7`.

The same build also adds 19 related checks covering HEVC VPS/SPS/PPS counts, the auxiliary
arrays, and `sEnc.sAlgCfg.sGOP.iNumOfTemporalLayer`.

## What we measured

Driving the encoder with out-of-range counts produces reproducible kernel panics in the encoding
daemon. Register state at fault (`x0=0x59`, `FAR=0x59`) shows a pointer derived from a small
integer, not attacker-controlled memory — an arithmetic consequence of the bad value, not a
controlled access.

## Why it is a denial of service, not a primitive

The value reaches arithmetic and then a null-ish dereference. No offset or content of the fault
is taken from the caller. The public description ("unexpected system termination") matches the
observed behaviour.

## Falsifier

Produce a non-panic outcome from an out-of-range temporal-layer count, or a fault whose address
is caller-influenced.

## Note

The audit build difference is what makes this worth listing at all: a check that exists in 27.2
and does not exist in 27.0.1 is a signal about what the vendor considered dangerous. It is not,
by itself, a memory-corruption primitive.
