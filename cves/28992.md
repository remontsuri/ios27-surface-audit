# CVE-2026-28992 — IOHIDFamily FastPath user client

| Field | Value |
|---|---|
| Component | `IOHIDFamily`, `IOHIDEventServiceFastPathUserClient` |
| Class | use-after-free from two races (claimed); privileged user client from an app |
| Our status | **measured — unreachable** from a sandboxed app |
| Build | iOS 27.0.1 (24A446), iPhone 14 (A15) |

## 1. What the public claim is

A published PoC describes two races in the FastPath user client: a caller-supplied entitlement
dictionary checked through selector 0, a close path on the termination thread, and an
open/work-loop path, with selectors 1 (close) and 2 (`copyEvent`) driving the client. The
author's report states the races were reproduced on iOS 26.3 and that no entitlement is needed to
open the client.

That would make it a memory-corruption bug in a kext an app can see, which is why it was worth a
probe rather than a note.

## 2. What was actually measured

A probe asked IOKit to match the service by every provider name associated with the family —
nine names, from `IOHIDEventService` to `IOHIDEventServiceFastPathUserClient` and
`AppleSPUHIDDevice`. Result, all nine:

```
IOHIDEventService                      rc=3758097089 n=0
IOHIDEventDriver                       rc=3758097089 n=0
IOHIDDevice                            rc=3758097089 n=0
IOHIDSystem                            rc=3758097089 n=0
AppleMultitouchDevice                  rc=3758097089 n=0
IOHIDInterface                         rc=3758097089 n=0
IOHIDEventServiceFastPathUserClient    rc=3758097089 n=0
AppleSPUHIDDevice                      rc=3758097089 n=0
IOHIDEventSystem                       rc=3758097089 n=0
HF no-service
```

`3758097089` is `0xE00002C1` = `kIOReturnNotPrivileged`. `n=0` means no service object was
returned, so no `IOServiceOpen` was attempted, so selectors 0/1/2 were never called and the race
was never set up. The probe source is not among the ones published in this repository; the run
output above is the record.

Statics agree with the runtime in the expected direction — the capability exists in the kernel,
only the match is refused:

| String, counted in the 24A446 kernelcache | Occurrences |
|---|---|
| `IOHIDEventServiceFastPathUserClient` | 11 |
| `FastPathHasEntitlement` | 2 |
| `FastPathMotionEventEntitlement` | 2 |

The contrast matters: `IOSurfaceRoot` matches from the same kind of app (that is how
[`cves/112477`](112477.md) was triggered), so this is a per-class sandbox policy, not a blanket
block on IOKit.

## 3. Why the status is what it is

`measured — unreachable`: the entry point does not exist for an ordinary app. The distinction is
worth stating plainly, because it is the difference between two very different kinds of "no":

| Statement | True here? |
|---|---|
| "we tried to trigger the races and the kernel held" | no — the races were never set up |
| "we cannot open the client at all" | yes — matching is refused before any selector |

No amount of trigger work improves this: the failure is upstream of the bug. It is not
`documented only` either, because a measurement was made and it produced a number.

## 4. The single falsifier

One of the nine provider names returning `n >= 1`, followed by `IOServiceOpen` returning
`0` (`KERN_SUCCESS`) with a non-null connection from a sandboxed app that carries no special
entitlement.

That single successful open reopens the branch; everything else in this file currently rests on
the nine refusals above.
