# CVE-2026-112665 — kernel memory layout disclosure

| Field | Value |
|---|---|
| Component | kernel (layout / KASLR information) |
| Class | information disclosure |
| Our status | **documented only** (no trigger available to test) |
| Build | iOS 27.0.1 (24A446) |

## Why it is listed

It is the second of the two leak candidates identified for the blocked chain, and the only one
whose public description matches the missing capability: determining the kernel memory layout,
i.e. defeating address randomisation.

## What was done

Nothing measurable. The public record gives a class and an affected range, not a trigger or a
proof of concept. Building a check would mean reconstructing the bug from the fix — the 27.2 diff
— which is a research task of its own, not a verification step.

Status **documented only** is the honest label: no evidence was produced here, in either
direction.

## What it would take to move it

1. Locate the fix in the 27.2 kernel diff (function-level comparison; addresses move between
   builds, code does not).
2. Identify the information that leaves the kernel and the shape of the output buffer.
3. Build a minimal trigger and confirm the returned data is kernel-derived.

Until step 3 succeeds, the CVE is a description, not a capability.

## Note

Recording it as "not tested" rather than "blocked" or "unavailable" matters: a later reader must
be able to tell whether the project tried and failed, or never had a means to try. This is the
latter.
