# CVE-2026-112688 — CoreMedia Dolby Vision RPU out-of-bounds write

| Field | Value |
|---|---|
| Component | CoreMedia DV-RPU parser (`CMGetDMVersionLevelFromRPU` and its block loop) |
| Class | stack out-of-bounds write, index and value from the parsed stream |
| Our status | **reproduced — partial** (write yes, delivery to the parser no) |
| Build | iOS 27.0.1 (24A446), iPhone 14 (A15) |

## What the vulnerability is

The RPU block parser reads a length, a block id and a payload, then stores parsed fields into
local arrays indexed by a counter taken from the stream:

* array `A`: 4 entries of 0x1c bytes at `struct+0x733c`, counter at `+0x7334`;
* array `C`: 5 entries of 0x24 bytes at `struct+0x726c`, counter at `+0x7268`.

The counter is compared against the array bound only to decide whether to increment it — the
store itself is not guarded, so an oversized count writes past the array.

## What we measured

The whole structure (0x73b4 bytes) lives in the function's **stack frame** (`sub sp, sp, #0x73c0`,
buffer at `sp+0xc`), and the frame ends exactly where the saved `x19/x20` and `x29/x30` begin.

By feeding a crafted block sequence through the real entry point, we observed the store land at
`struct+0x73c8` — 0x14 bytes past the end of the structure, i.e. into the saved registers. The
written values were ours.

The write goes through two branches: a short one that stores `+0/+2/+4/+6`, and an extended one
(triggered when the field at `+0x25c` is `>= 0x13`) that also stores `+8 … +0x16`. With index 5
the extended branch covers `x29` and the low half of `x30`.

## Why it stops at a crash

The epilogue is `retab`. A partially overwritten link register fails pointer authentication and
the process dies; control flow is not redirected. Without the crash, only the data-only registers
`x19/x20/x21` are reachable.

Delivery is the open question: there are **no direct callers** of the RPU entry point inside
CoreMedia itself (536 154 instructions scanned), no matching strings in VideoToolbox,
AVFoundation or the media daemons, and feeding a Dolby Vision stream through `AVPlayer` and a
direct `VTDecompressionSession` decoded fine without ever reaching the parser.

## Current position

The parser bug is real and measurable in isolation. Turning it into a primitive needs an entry
point that delivers a crafted RPU to the parser from a file. That is exactly branch 2 in
[`ROADMAP.md`](../ROADMAP.md), with a three-run, three-day stop condition.

## Falsifier

Produce a crash report whose process is a media daemon, caused by a file played through a normal
API. Any such report reopens the delivery question with a concrete target.
