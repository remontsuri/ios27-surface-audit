# CVE-2026-112476 — kernel out-of-bounds read

| Field | Value |
|---|---|
| Component | kernel |
| Class | out-of-bounds read / denial of service |
| Our status | **documented only** (corrected: not an info leak) |
| Build | iOS 27.0.1 (24A446) |

## Why it is in the register with a correction

An early internal note filed this CVE as a candidate info leak. That was wrong, and the register
keeps the correction rather than deleting the row: a wrong classification that is silently removed
comes back later.

## What the public material supports

An out-of-bounds read in a kernel path, reported as a denial-of-service class issue. There is no
public indication that the read result is returned to the caller — which is what would make it a
leak.

## What would change the status

A measured read whose *content* reaches user space in a form derived from kernel memory. A crash
from reading past a buffer is not that.

## Falsifier

Produce a user-visible buffer containing kernel-derived bytes originating from this path.

## Note on process

This entry exists because the project's rule is that corrections are recorded, not overwritten.
A register that only contains the conclusions which survived looks cleaner and is less useful.
