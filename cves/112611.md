# CVE-2026-112611 — CoreGraphics type-5 shading

| Field | Value |
|---|---|
| Component | CoreGraphics, `cg_shading_type5_draw` (PDF type-5 shading) |
| Class | out-of-bounds write, out-of-bounds read |
| Our status | **reproduced — partial** |
| Build | iOS 27.0.1 (24A446), iPhone 14 (A15) |
| Detail | [`docs/08`](../docs/08-pdf-shading-sites.md), summary [`docs/05`](../docs/05-pdf-cg5-write.md) |

## What we reproduced

A malformed type-5 shading produces two distinct faults inside the shipped binary:

```
write  func+0x740   str  wzr, [x22, #0xc]     ; x22 = x24 + x28*16 ; stores 32-bit ZERO
read   func+0x7AC   ldr  q0,  [x9]            ; x9 = *(x19 + x24*8) ; 16 bytes, copied to output
```

Over 63 crash reports: the write formula holds 20/20 with `x28 = 1`, giving `far = bits(double) +
0x1c`; the read path is explained 25/25 by "the over-read slot holds `bits(double)` of the shading
function output" and 0/25 by the competing "decoded coordinate" hypothesis. An emulator executing
the real bytes of the shipping binary reproduces every `far` on both paths.

## What we could not get

Steering the address to something useful. Because the address equals a double's bit pattern, it can
only take values that a PDF real can express (bounded near 1e±38). A denormal chosen to encode
`0x0000000010000000` did not produce a fault at all on a clean build, while the ordinary-double
control produced the canonical report. The write half is therefore a **zero-write to
double-shaped addresses**, not an arbitrary write.

## Status rationale

`reproduced — partial` rather than `reproduced — DoS` because the read half — 16 bytes from a
file-influenced address, copied into renderer output — is leak-shaped and has not been tested to
completion. It is not `documented only`, because the crash and the arithmetic are ours.

## Fixed in 27.2

The shading initialiser gained a component/dimension check
(`CG-SEC-187882049: invalid function for type 5 shading (range dimension does not match color
space)`). The audit build has no such check and computes `components << 1` before reading `Decode`.

## Falsifiers

* stored data at the write site is non-zero;
* a document drives the site to a real mapping;
* the 16 bytes read at the read site reach caller-readable data.
