# CVE-2026-112611 — CoreGraphics type-5 shading write

| Field | Value |
|---|---|
| Component | CoreGraphics, PDF type-5/6/7 shading; reached in the system preview stack |
| Class | out-of-bounds write |
| Our status | **reproduced — partial** (address controlled, value not) |
| Build | iOS 27.0.1 (24A446), iPhone 14 (A15) |
| Related writeup | [`docs/05-pdf-cg5-write.md`](../docs/05-pdf-cg5-write.md) |

## Public claim

A crafted PDF drives an out-of-bounds store inside the shading evaluator with a
"value-controlled" payload, i.e. both the destination address and the written data come from the
document.

## What we measured

A minimal PDF with a type-5 shading whose function dimension exceeds the component count moves an
index past the end of the coefficient array. The store is:

```
mov x25, #0x3ff0000000000000
str d2,  [x14]
```

The destination (`x14`) follows the shading mesh — it changes with document parameters. The data
register `d2` holds the double `1.0`, loaded immediately before the store.

## The control experiment that decided it

Two documents were rendered: one with `C0 = C1 = 2.0`, one with default values. Both produced the
same fault payload: `far = 0x3ff000000000001c` — the address moved, the written value did not.

So the "value-controlled" half of the claim does not reproduce on this build: the payload is the
code's own constant.

## Consequence

A write of a known constant to a semi-chosen address is a crash generator. It reproduces as
termination of the preview/thumbnail extension — a userland denial of service, not a write
primitive.

## Falsifier

Two documents differing in one parameter must produce two different data values at the store. Any
dependence of `d2` on file content reopens the branch.
